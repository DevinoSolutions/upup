A failed OAuth token exchange in `GET /auth/:provider/cb` is now mapped per cause instead of always answering `502`. When the provider rejected the authorization code or your OAuth app (a provider `4xx` other than `408`/`429`, or an OAuth `error` in a `200` body) the route answers `424` (Failed Dependency): signing in again cannot succeed until the user starts afresh or the app's client id, secret or redirect URI is fixed. When the provider was unreachable or timed out, answered `5xx`/`429`/`408` or another non-`4xx` error, or sent a malformed `200` (no token and no error, or a body that is not JSON, which used to escape as a generic `500`), it answers `502`: the failure is on the provider's side and signing in again may work. The callback URL itself is never replayable in either case. The `{ error, code: 'AUTH_PROVIDER_ERROR' }` body, the `x-upup-request-id` header and the cleared nonce cookie are unchanged. A `424` also passes through Cloudflare, which replaces an origin `502` with its own plain-text page. Clients that matched on `502` for this route should also handle `424`, or match the `AUTH_PROVIDER_ERROR` code.
